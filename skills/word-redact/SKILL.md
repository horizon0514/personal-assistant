# 文档脱敏 Skill

把一份文档里的个人/机密信息抹掉或打码,**产出一个可以放心外发的副本**(原件保持不动)。所有读写都用内置的 **office_cli** 工具完成(底层 OfficeCLI,直接读写 OpenXML,无需装 Office)。主要面向 Word(.docx),Excel(.xlsx)、PPT(.pptx) 同理。

> office_cli 的入参是一个 `args` 数组(不含 `officecli` 本身),逐项一个 token。下文示例同时给出「可读命令」和「args 数组」。读类子命令(view/get/query)自动执行;改文件的(set/remove/batch…)会向用户弹审批。

## 核心原则(先记住)
1. **绝不改原件。** 脱敏不可逆——一旦替换,被抹掉的原文就找不回来了。第一步永远是复制一份副本,只在副本上操作。
2. **宁可多抹,不可漏抹。** 漏一个手机号就等于没脱敏。识别要全(正则 + 通读),覆盖要全(正文 + 页眉页脚 + 批注 + 元数据)。
3. **抹完必须核验。** 重新通读 + 重跑识别正则,确认零残留,再交付。

## 整体流程
1. 复制副本 → 2. 通读 + 识别敏感项 → 3. 在副本上替换(结构化 PII 走正则,姓名/单位等走逐个替换)→ 4. 收尾盲区(元数据/批注/修订)→ 5. 核验零残留。

---

## 第 1 步:复制副本
用 exec_shell 复制,产出一个**全新的、之前没操作过的**输出名(如 `xxx-脱敏.docx`),**后续所有 office_cli 命令都指向这个副本的绝对路径**:
```
cp "/abs/原报告.docx" "/abs/原报告-脱敏.docx"
```
(office_cli 没有复制子命令,所以这步用 shell。会弹一次审批,确认无误即可。)

> ⚠️ **常驻进程坑(务必懂):** OfficeCLI 对每个文件会起一个**常驻进程把文档留在内存里**加速后续命令,改动先进内存、**不即时落盘**。由此两条铁律:
> - **输出名要全新**,别 `cp` 覆盖到一个 office_cli 已打开(有常驻)的路径——否则命令会连到旧的内存副本,出现「改了像没改 / 0 matched / 复制到空壳」。
> - **全部改完后必须 `close`(见第 5 步)**,把内存刷到磁盘,文件才真正成型、能被 Word 打开和外发。

## 第 2 步:通读 + 识别

### 先确认范围(动手前必问)
**「哪些算敏感」取决于这份脱敏稿给谁看、做什么用——不要自己猜。** 同一个公司名,内部流转无所谓,发公网就得抹。所以开抹前先问用户两件事:
1. 这份稿子**给谁、做什么用**(外发客户?发公网?内部跨部门?);
2. 有没有**特别要保留或特别不能漏**的(如「公司名保留,只抹人名和电话」)。

### 用三层抓全敏感项
把全文读出来:
```
officecli view /abs/原报告-脱敏.docx text
→ office_cli args: ["view","/abs/原报告-脱敏.docx","text"]
```
然后按三层识别:
- **① 固定形态 PII(正则确定性命中,基本盘):** 手机号、身份证、银行卡、邮箱、固话、统一社会信用代码、车牌、IP、护照号、地址门牌等。见第 3a 正则表。
- **② 法规「敏感个人信息」当清单(《个人信息保护法》类目):** 姓名/身份证/护照等身份信息、生物识别、宗教信仰、特定身份、**医疗健康**(病历/诊断)、**金融账户**(账户/交易)、**行踪轨迹**(住址/行程/定位)、不满 14 周岁未成年人信息。逐条对照文档过一遍。
- **③ 上下文相关(正则抓不到,靠通读判断):** 人名、单位/公司名、具体地址、项目代号、内部系统名、合同金额、薪资、未公开的商业数据等。这类最容易漏。

### 列清单给用户过目
②③ 里边界模糊的(人名、公司名、内部代号),**把识别出的清单列给用户确认一眼再替换**——让用户拍板比你赌强。拿不准的,宁可抹掉。

### 纯本地模式(对隐私敏感时)
③ 的人名/机构/地址若靠模型「通读全文」来找,文本会发给云端模型。**要求绝不外传时**,改走纯本地:① 的结构化 PII 全用正则(本就在本机);③ 用**本地 NER** 抓人名/机构/地点——见 `research/redact-local-ner`(transformers.js + ONNX,onnxruntime 本机 CPU 跑,文档不出本机)。它返回实体表面串,照样喂回下面的 `set --find/--replace`。这样全程零外传。

定位某类文本可用 query 的 `--find`(只读、不改):
```
officecli query /abs/原报告-脱敏.docx run --find "@"   # 找含 @ 的(邮箱)
→ ["query","/abs/原报告-脱敏.docx","run","--find","@"]
```

## 第 3 步:替换(在副本上)
**关键:对根节点 `/` 做替换,会递归覆盖正文 + 所有页眉 + 所有页脚(以及脚注等),一次到位。** 不要只对 `/body` 做,那样会漏掉页眉页脚。

`set` 的 `--find` 默认是字面子串;**加 `r"..."` 前缀启用正则**(.NET 正则,支持前后界断言 `(?<!…)`/`(?!…)` 和反向引用 `$1`)。

### 3a. 结构化 PII —— 正则替换
```
officecli set /abs/原报告-脱敏.docx / --find 'r"(?<!\d)1[3-9]\d{9}(?!\d)"' --replace '[手机号]'
→ ["set","/abs/原报告-脱敏.docx","/","--find","r\"(?<!\\d)1[3-9]\\d{9}(?!\\d)\"","--replace","[手机号]"]
```

> ⚠️ **两个必须遵守的坑:**
> 1. **顺序:先长后短、先具体后笼统。** 比如先抹 18 位身份证,再抹 11 位手机——否则手机号正则 `1[3-9]\d{9}` 会先把身份证里的一段数字吃掉,留下残缺数字。推荐顺序:身份证 → 统一社会信用代码 → 银行卡 → 手机 → 固话 → 邮箱/其它。
> 2. **永远加前后界断言** `(?<!\d)…(?!\d)`,防止把更长数字串里的一截误匹配。

**常用正则速查**(都已含数字边界,`--replace` 按需换成你的占位符):

| 类型 | `--find` 正则 |
|---|---|
| 身份证(18 位) | `r"(?<!\d)\d{17}[\dXx](?!\d)"` |
| 手机号 | `r"(?<!\d)1[3-9]\d{9}(?!\d)"` |
| 银行卡(16–19 位) | `r"(?<!\d)\d{16,19}(?!\d)"` |
| 邮箱 | `r"[\w.+-]+@[\w-]+\.[\w.-]+"` |
| 固定电话 | `r"(?<!\d)0\d{2,3}-?\d{7,8}(?!\d)"` |
| 统一社会信用代码 | `r"(?<![0-9A-Z])[0-9A-HJ-NP-RT-UWXY]{2}\d{6}[0-9A-HJ-NP-RT-UWXY]{10}(?![0-9A-Z])"` |
| 车牌 | `r"[京津沪渝冀豫云辽黑湘皖鲁新苏浙赣鄂桂甘晋蒙陕吉闽贵粤青藏川宁琼][A-Z][A-Z0-9]{5,6}"` |
| IPv4 | `r"(?<!\d)(?:\d{1,3}\.){3}\d{1,3}(?!\d)"` |

### 3b. 三种脱敏强度(和用户确认要哪种)
- **整体打码(最稳):** 直接替换成 `[手机号]`/`████`。彻底,但丢失格式信息。
- **保留部分掩码:** 用捕获组保留首尾。手机保留前 3 后 4:
  `--find 'r"(?<!\d)(1[3-9]\d)\d{4}(\d{4})(?!\d)"' --replace '$1****$2'` → `138****5678`
  身份证保留前 6 后 4:
  `--find 'r"(?<!\d)(\d{6})\d{8}(\w{4})(?!\d)"' --replace '$1********$2'`
- **化名(可读性最好):** 人名/单位换成一致的化名,**同一实体必须映射到同一化名**(张三→某甲、李四→某乙、ABC公司→某公司A)。你自己维护这张映射表,逐个字面替换:
  ```
  officecli set /abs/...-脱敏.docx / --find '张三' --replace '某甲'
  ```

### 3c. 非结构化(人名/单位/地址)
按第 2 步列出的清单,逐个用**字面** `--find`(不加 `r"..."`)替换。注意同名片段误伤(比如「王」单字),尽量用全名或带上下文。

### 3d. 批量(可选,省审批次数)
模式很多时,用一次 `batch` 把多条 set 合并成一个 open/save 周期(只弹一次审批)。命令数组里每项是 `{"command":"set","path":"/","props":{"find":"...","replace":"..."}}`:
```
officecli batch /abs/...-脱敏.docx --commands '[{"command":"set","path":"/","props":{"find":"r\"(?<!\\d)\\d{17}[\\dXx](?!\\d)\"","replace":"[身份证]"}},{"command":"set","path":"/","props":{"find":"r\"(?<!\\d)1[3-9]\\d{9}(?!\\d)\"","replace":"[手机号]"}}]'
```
batch 里命令**按顺序**执行,正好满足「先长后短」。

## 第 4 步:别漏的盲区
正文好抹,真正泄密的常是这些——都要处理:
- **页眉 / 页脚 / 脚注:** 对 `/` 做的替换(第 3 步)已递归覆盖,不必单独处理。但务必确认你是对 `/` 而不是 `/body` 做的。
- **文档元数据(作者、最后修改人):** 这是最容易漏、最直接暴露身份的地方。清掉:
  ```
  officecli set /abs/...-脱敏.docx / --prop author=匿名 --prop lastModifiedBy=匿名
  → ["set","/abs/...-脱敏.docx","/","--prop","author=匿名","--prop","lastModifiedBy=匿名"]
  ```
- **批注:** 评审批注常带姓名/内幕。整段删除最干净:`query ... comment` 找出后,逐个 `remove /abs/... <批注路径>`。
- **修订/痕迹(tracked changes):** 修订记录里藏着改之前的原文和改动人。先 `view ... issues` 或 `query ... revision` 看有没有,有就处理掉再交付。
- **图片里的文字:** 正则和 office_cli 都抹不到图片中的文字——如果文档里有截图含敏感信息,提醒用户,这部分需另行处理。

## 第 5 步:核验 + 落盘(交付前必做)
1. 重新通读:`officecli view /abs/...-脱敏.docx text`,人眼扫一遍有没有漏网的。
2. 重跑识别正则确认零残留(只读,`query --find` 不改文件):
   ```
   officecli query /abs/...-脱敏.docx run --find "@"     # 还有邮箱? 命中为 0 才算干净
   → ["query","/abs/...-脱敏.docx","run","--find","@"]
   ```
   对每类 PII 各查一遍,命中都为 0 才放心。
3. 确认元数据已清:`officecli get /abs/...-脱敏.docx /` 看 author / lastModifiedBy。
4. **落盘:** `officecli close /abs/...-脱敏.docx` —— 把内存改动刷到磁盘并停掉常驻,文件这才真正成型、可外发。这步别省。
   ```
   → ["close","/abs/...-脱敏.docx"]
   ```
5. 跟用户报告:抹了哪几类、各多少处、用的哪种强度、副本绝对路径。

## 规矩
- **第一步必复制副本,绝不在原件上跑替换。** 替换不可逆。
- 替换(set/remove/batch)是改文件操作,office_cli 会弹审批——执行前先用一句话告诉用户:在哪个副本、抹哪几类、用什么占位/掩码。
- 拿不准某串算不算敏感(尤其人名、内部代号),宁可问用户或一并抹掉,别赌。
- **改完一定 `close` 落盘**(第 5 步),否则交付的是没刷盘的空壳/旧内容。输出名要全新,别覆盖已打开的文件。
- 命令失败先读 stderr:多半是路径不对(必须绝对路径)、正则转义错(args 数组里反斜杠要按 JSON 再转义一层)、或文件被占用。按错误修正,别瞎试。
- 出现「明明替换了却像没生效 / 0 matched」十有八九是常驻进程拿了旧内存:先对该文件 `close` 再重来。
- 子命令/属性现查:`officecli help docx`、`officecli set --help`、`officecli query --help`。
